# CATIA V5 Automation / External Control: Available Methods to Drive CATIA from an Outside Program

Scope note: all findings below are about CATIA V5 (COM-based "CAA Automation"/V5 Automation API), on Windows, not CATIA V6 / 3DEXPERIENCE (which a forum source explicitly says uses a different, non-"CATIA.Application" connection model). Nearly all sources are forums (eng-tips.com, 3dconnexion forum, Stack Overflow mirrors), community wrapper-library docs (pycatia), and IBM/PTC support notes that reference Dassault's CAA documentation rather than being the official Dassault docs themselves (official DS CAA/V5Automation.chm documentation is license-gated and was not directly accessible during this research). This should be treated as strong circumstantial/practitioner evidence, not primary-source certainty, and is flagged inline wherever a single forum poster is the only source.

## What is CATIA V5's Automation API, and what languages/technologies can call it (VBA, VBScript, VB6, .NET, Python)?

### Takeaway
CATIA V5 exposes its object model (Application, Documents, ActiveDocument, Selection, Viewer/Viewpoint, etc.) as a set of COM type libraries ("CAA Automation" / V5Automation), documented historically in the `V5Automation.chm` help file. It can be driven in-process by VBA/CATScript macros, and out-of-process by any COM-capable language on Windows — VBScript, VB6/VBA in other Office apps, .NET (C#/VB.NET) via generated Interop assemblies, and Python via `pywin32` (`win32com.client`) or `comtypes` — all using the same underlying COM objects, with `win32com.client.Dispatch("CATIA.Application")` / `GetObject(, "CATIA.Application")` as the standard entry point.

### Cited Findings
- The reference for the object model is the `V5Automation.chm` help file shipped with CATIA; a forum poster advises "READ IT BEFORE writing your scripts!" — [python-list mailing list, 2004](https://www.python.org/pipermail/python-list/2004-November/286299.html)
- Standard Python connection pattern: `import win32com.client; catapp = win32com.client.Dispatch("CATIA.Application")`, attaching to a running CATIA session — [python-list mailing list, 2004](https://www.python.org/pipermail/python-list/2004-November/286299.html)
- The `pycatia` library (main project `evereux/pycatia`, forks `mokrueger/pycatia`, `ZhangJzhao/pycatia`) is a pure-Python wrapper built by "scraping through the contents of the V5Automation.chm help file to re-construct all the classes and methods for python," requiring Python ≥ 3.9 and a running CATIA V5 on Windows; some methods are reached by running VBA via `Dispatch('CATIA.Application').SystemService.Evaluate()` where direct COM calls don't work from Python — [GitHub: evereux/pycatia](https://github.com/evereux/pycatia); [PyPI pycatia](https://pypi.org/project/pycatia/)
- `pycatia` is explicitly labeled alpha software with uneven coverage because the author has "limited access to CATIA licences/workbenches" — [GitHub: evereux/pycatia](https://github.com/evereux/pycatia)
- VBScript attach pattern: `Set CATIA = GetObject(, "CATIA.Application")`, with a `CreateObject` fallback (`On Error Resume Next`, check `Err.Number`) if no instance is already running — [eng-tips thread 368167](https://www.eng-tips.com/threads/catia-v5-vba-vb-vbscript-searching-activating-part-design-within-product-structure.368167); [Dassault training notes](https://www.scribd.com/doc/251080437/Catia-Automation)
- A Stack Overflow mirror question "catia macro from python" shows a user trying to run a `.CATScript` macro from Python via `win32com.client.Dispatch("CATIA.Application")` to open CATIA and process a `.CATPart` — [Stack Overflow mirror](https://kiwix.lema.org/stackoverflow.com_en_all_2023-11/questions/49610628/catia-macro-from-python)
- For .NET: "the usual path is to reference CATIA's type libraries in Visual Studio (or generate the interop DLLs with `tlbimp.exe`), then connect with `GetActiveObject` or `CreateObject`." Example C# pattern cited from forums: `INFITF.Application CATIA = (INFITF.Application)Marshal.GetActiveObject("Catia.Application");` — [eng-tips thread 453715 "Interop.Infitf.dll — where is that from"](https://www.eng-tips.com/viewthread.cfm?qid=453715)
- `INFITF` is CATIA's core COM type library; other CATIA object areas live in separate type libraries that must be referenced too, e.g. `MECMOD`, `PARTITF`, `ProductStructureTypeLib`, `KnowledgewareTypeLib` — accessing `Product`-level (assembly) objects specifically requires the "ProductStructure Object Library," not the base CATIA interface — [eng-tips thread 453715](https://www.eng-tips.com/viewthread.cfm?qid=453715); [python-list mailing list, 2004](https://www.python.org/pipermail/python-list/2004-November/286299.html)
- A real-world VB.NET automation project is reported to "work fine from Catia R18 to R26," after the author switched from early-bound CATIA type-library references to late binding to fix version-compatibility issues — [eng-tips thread 459898 "CATIA V5 R29 automation crash in drafting with VB.net code"](https://www.eng-tips.com/threads/catia-v5-r29-automation-crash-in-drafting-with-vb-net-code.459898/latest)
- A forum opinion (unverified, single source): "VB.NET is definitely more friendly to Automation than C#," though other posters said both are equally capable; another poster called the COM interface itself "the difficult part" regardless of language — [eng-tips thread 510766 "CATIA, C# dlls instead of C++ CAA"](https://www.eng-tips.com/threads/catia-c-dlls-instead-of-c-caa.510766/latest)
- `comtypes` is cited by a python-win32 mailing-list contributor as a viable alternative to `pywin32`, able to "generate module definitions from TLB files" — [python-win32 mailing list](https://mail-archive.com/python-win32@python.org/msg11017.html)
- Early-binding pitfall: generating early-bound wrappers (`makepy`) for the "CATIA V5 Interfaces Object Library" can break other applications that also use early binding against COM; the workaround is late binding (e.g., `win32com.client.dynamic`) — [code.activestate.com recipe summary via search](https://code.activestate.com/recipes/347243) (direct fetch of this page was blocked in this research session's network sandbox; relayed via search-engine summary only)
- Known Python COM interop defect: passing arrays by reference from Python to CATIA methods does not work reliably — a VBScript equivalent modifies the array in place as expected, but the Python/`pywin32` call "just passes the array back out unmodified" — [python-win32 mailing list thread, 2014](https://www.python.org/pipermail/python-win32/2014-July/013244.html)
- The `"CATIA.Application"` COM ProgID is V5-specific; a forum user reports it "stopped working with CATIA V6" — confirming this whole approach does not carry over to V6/3DEXPERIENCE — [eng-tips thread 398347 "accessing catia v6 from excel vba"](https://eng-tips.com/threads/accessing-catia-v6-from-excel-vba.398347)
- When multiple CATIA versions/instances are installed, `GetObject`/`GetActiveObject` returns whichever instance is first in the Windows Running Object Table (ROT) — there is no simple built-in way to target a specific running instance; one developer describes a nontrivial marshaling workaround to pick a specific instance — [Microsoft forum via search](https://learn.microsoft.com/he-il/archive/msdn-technet-forums/a8cb7e73-2c8e-4ec0-ab75-d8f2db7aa091); [cnblogs repost of a .NET-specific-instance technique](https://www.cnblogs.com/jason2004/p/8534671.html); [Stack Overflow mirror "is it possible to target specific com instances of catia"](https://kiwix.lema.org/stackoverflow.com_en_all_2023-11/questions/26934746/is-it-possible-to-target-specific-com-instances-of-catia)

### Inferences
- For a controller-input program, Python via `pywin32` (`win32com.client.Dispatch`/`GetObject`) or the `pycatia` wrapper is the lowest-friction path to prototype against CATIA's object model; C#/.NET via generated Interop assemblies (`INFITF`, `MECMOD`, etc.) is the more "native Windows app" route and is well precedented, provided late-binding or carefully version-matched interop DLLs are used to avoid breakage across CATIA service packs.
- Because the ROT only exposes "a" running CATIA instance, a driver application should assume single-instance CATIA usage, or build in the more involved specific-instance marshaling workaround if multi-instance support is ever needed.
- Given the documented array-by-reference bug and other partial-coverage gaps in pure-Python/pywin32 calls, some advanced automation calls may need to be proxied through an in-CATIA VBA macro invoked via `SystemService.Evaluate()` (as `pycatia` itself does) rather than called directly from Python.

### Gaps
- No access to the authoritative, current Dassault CAA/V5Automation.chm documentation itself (paywalled/license-gated) — all API surface claims here are secondhand via forums or the `pycatia` project's reverse-engineered docs, not confirmed against primary DS documentation.
- No confirmed information on using IronPython or other .NET-hosted dynamic languages beyond one dead-end mailing list thread about COM object issues — not independently resolved.

## Does the Automation API allow controlling the 3D viewport camera (pan/zoom/rotate/predefined views), triggering arbitrary toolbar commands/macros, and reading/manipulating selection and the specification tree?

### Takeaway
Yes to all three, with caveats: camera/view manipulation is exposed through `Viewpoint3D`/`Camera3D`/`Viewer3D` objects (zoom factor, up/sight direction, explicit `Rotate`/`Translate` methods) and reports of some orientation inaccuracies; arbitrary commands can be fired via `Application.StartCommand("<command name or internal ID>")`, but this is officially described (via IBM support) as safe only for one-shot, non-interactive commands, not multi-step interactive tools; and the `Selection` object (`Document.Selection`) supports `Add`, `Clear`, and `Search` (with query strings) against the specification tree, with several forum-documented quirks/pitfalls.

### Cited Findings
- **Camera/view control:** The `pycatia`-documented `Viewpoint3D` interface (reverse-engineered from CAA VB help, generated from "V5Automation files from CATIA V5 R28") includes a zoom property described as "Returns or sets the zoom factor associated with the viewpoint," plus methods to set origin, up direction (`PutUpDirection`), and sight direction (`PutSightDirection`) — [pycatia docs via search summary](https://pycatia.readthedocs.io/en/latest/api/pycatia/in_interfaces/viewpoint_3d.html) (direct fetch blocked in this session's network sandbox; relayed via search-engine summary)
- A 3D camera object stores a viewpoint; example pattern cited from a forum: create a camera via `CATIA.ActiveWindow.ActiveViewer.NewCamera()`, set a zoom factor on it, then reassign its viewpoint back to the viewer — [search-engine summary of pycatia/forum material]
- The 3D viewer itself exposes a `Rotate` method taking an axis and an angle in degrees, and a `Translate` method taking a vector — described as "the closest thing to a programmatic pan and rotate on the viewer itself" — [search-engine summary, pycatia `viewer_3d` docs]
- A forum user building a viewpoint-setting macro (first in CATScript, later ported to VBA) reported the resulting view came out "slightly rotated" versus the intended target — a documented accuracy caveat — [eng-tips thread via search, qid 472826](https://www.eng-tips.com/viewthread.cfm?qid=472826)
- Setting `ActiveViewer.Viewpoint3D` directly to an isometric viewpoint, then calling `StartCommand "Fit All In"`, is reported by one forum user to "work perfectly for rotating the part to isometric" — [eng-tips forum thread, via search]
- `DefineIsometricView(x1,y1,z1,x2,y2,z2)` exists but is fiddly: a poster trying to get a specific corner-isometric orientation got the back view instead, and notes CATIA's default axis convention (YZ plane = front, XY plane = top) — [eng-tips thread 351599 "DefineIsometricView query"](https://eng-tips.com/threads/defineisometricview-x1-y1-z1-x2-y2-z2-query.351599)
- **Triggering commands:** `Application.StartCommand` takes either a display name or an internal command ID string; example cited: the display label "Expand Selection" corresponds to internal ID `"SpecificationsLevelSelect"`, and a poster reports the internal ID kept working after the English display-label string stopped working (likely due to localization/version change) — [eng-tips, cited via search summary]
- IBM support guidance (paraphrased by a forum poster, consistent across multiple threads): `StartCommand` "is useful to execute one-shot (not interactive) commands; it is not safe for interactive commands" that require further user interaction/dialogs — [IBM support note, cited via eng-tips/search summary]
- Available command names for `StartCommand` can be discovered via the View menu's "Command List…" (lists commands available for your installed licenses); PTC/Windchill documentation separately points to Tools > Customize > Commands as another place action/command names are listed — [search summary]; [PTC Windchill docs on CATIA V5 macro/action names](https://support.ptc.com/help/wnc/r12.1.0.0/en/Windchill_Help_Center/WWGMToolkit/wwgmtoolkit_create_CATIAV5_MACRO_Actions.html)
- Some commands require a pre-existing selection before `StartCommand` will work ("You need first to select something and then go with your command") — [eng-tips, cited via search]
- Workbench-switching caveat: a poster found `StartCommand`/`StartWorkbench` style calls did not reliably switch the active workbench before running an aliased command, causing the macro to fail — [eng-tips thread, cited via search]
- `Application.StartWorkbench("GPSCfg")`-style calls are the documented pattern to switch workbenches from a macro; but one user found calling `StartWorkbench("PrtCfg")` to enter Part Design actually **created a new Part document** and switched `ActiveDocument` to it, rather than just changing context on the existing document — an important side-effect caveat — [eng-tips thread, cited via search]
- A presentation/training deck specifically warns: "Not all CATIA V5 functions have been exposed in the type libraries" and advises against switching workbenches while recording a macro — [search summary of RAND-style training deck]
- **Selection / spec tree:** `Document.Selection` is the entry point; common pattern `CATIA.ActiveDocument.Selection.Add(ObjectToAdd)` with `.Clear()` to empty it — [pycatia docs summary](https://pycatia.readthedocs.io/en/latest/api/pycatia/in_interfaces/selection.html)
- `Selection.Search("Name=...,all")`-style query strings can search the spec tree by instance name; another example uses a `CATAsmSearch` filter to select all products/parts in an assembly — [eng-tips threads, cited via search]
- Documented pitfalls: (a) one user reported `Search` returned nothing until a manual search had first been run once interactively after CATIA launched; (b) `Add`ing a wrong object type (e.g. a Document instead of a Product/feature) throws runtime error 438 ("object doesn't support this property or method"); (c) another user found `Selection.Count` stayed at zero even though the tree visibly showed the item highlighted — [eng-tips threads, cited via search]
- The `pycatia` docs note that when the active window shows the specification tree, the correct `Selection` to use is the one tied to the Product document — using the wrong document's Selection object gives "unpredictable" results — [pycatia docs summary]

### Inferences
- View/camera automation is sufficient for discrete, "snap to" operations (predefined views, explicit zoom/rotate-by-angle) but the documented rotation-accuracy complaint and the general COM call latency suggest the Automation API alone is not well-suited to smooth, continuous, joystick-driven real-time orbiting — this supports pairing it with input-injection or a tight polling loop for continuous motion (see next section).
- `StartCommand` is adequate for one-shot toolbar actions (e.g., switch to isometric, fit all, run a specific tool) that a controller button-press should map to, but multi-step/interactive CATIA commands (e.g., an interactive sketch tool requiring several clicks) are explicitly unsupported this way per IBM guidance — these would need either a dedicated macro that performs the full operation non-interactively, or synthetic UI input.
- Given the workbench-switching side effect (creating a new document), a controller mapping for "switch workbench" should be tested carefully per-workbench and may be safer done by triggering the equivalent toolbar/menu command (`StartCommand` with the UI command name) rather than `StartWorkbench` directly, or avoided in favor of letting the user pick workbenches via the UI.

### Gaps
- No primary-source, exhaustive list of `Viewpoint3D`/`Camera3D`/`Viewer3D` method signatures was retrievable (readthedocs and official DS doc access were both blocked in this research session) — exact parameter types/units for `Rotate`/`Translate` need to be confirmed against the installed release's `V5Automation.chm` or `pycatia` source directly.
- No confirmed complete list of internal `StartCommand` IDs vs. display names; this appears to be something practitioners discover ad hoc (via "Command List…" or trial and error), and Dassault does not publish a master list per the IBM note that "hidden"/UI-activation commands are "not exposed in Catia documentation nor in Catia available command lists."

## Which CATIA V5 release levels (R18–R2x / V5-6R20xx) expose which parts of the API, and are there known version differences/deprecations?

### Takeaway
There is no single authoritative version-by-version Automation API changelog available in the sources found; what evidence exists is scattered compatibility bug reports (R18→R20, R18→R21) and release-naming clarifications, plus a practitioner report that a late-bound VB.NET automation codebase "works fine from Catia R18 to R26." Release naming after ~2010 uses a year-based scheme (e.g. "V5-6R2020") that maps to an internal R-number (e.g. R2020 = "R30"), which is useful for matching documentation/forum posts to a specific internal version number.

### Cited Findings
- Dassault's CAA deprecation policy requires a deprecated API to point to its replacement, per the CAA guide "CAA V5 Authorized API Identification, Usage, Deprecation, and Stability" (referenced by an IBM support record on a deprecated contextual-links API) — [IBM support, cited via search](https://www.ibm.com/support/pages/apar/HD88058)
- Documented cross-version breakage examples: a CATVBA script that ran correctly in R18 failed in R20 (IBM closed this as "unreproducible in next release"); a Knowledgeware action created in V5R18 failed in R21 (closed as "program error"); `Product.CreateReferenceFromName` was reported to sometimes return a reference to a different object than the one passed in — [IBM support notes, cited via search]
- A practitioner report: a VB.NET automation project "works fine from Catia R18 to R26" after switching from early-bound CATIA type-library references to late binding; a related R29 VB.NET project still hit a new drafting-method crash, suggesting ongoing method-level instability even on late binding — [eng-tips thread 459898](https://www.eng-tips.com/threads/catia-v5-r29-automation-crash-in-drafting-with-vb-net-code.459898/latest)
- IBM support references a CAA guide section "About VB, VBA, Debug, and Portability" that documents manual adjustments sometimes needed when porting automation code across CATIA versions — [IBM support, cited via search]
- A command-ID stability issue: one poster found the English display-name string for a command ("Expand Selection") stopped working across a version change, while the internal command ID (`"SpecificationsLevelSelect"`) kept working — implying display names used with `StartCommand` are less version-stable than internal IDs — [eng-tips, cited via search]
- Official third-party support status: PTC notes that Dassault Systèmes has terminated official support for CATIA V5 R19 and R20 (relevant to anyone relying on official patches/support for those specific releases) — [PTC support article CS271676](https://www.ptc.com/en/support/article/CS271676)
- Release-naming clarification: Theorem Solutions' CAD-interoperability release notes list "V5-6R2017" through "V5-6R2020" as a sequence of year-named releases, and specifically equate "V5-6R2020" with the internal designation "R30" ("Added support for CATIA V5-6R2020 (R30)") — [Theorem Solutions MC5NX V23.1 Product Release notes](https://www.theorem.com/hubfs/PRN%20and%20Documentation/MC5NX/MC5NX_V23.1_Product%20Release.pdf)
- Theorem's documentation separately lists the "Dassault Multi-CAD API" revision alongside each CATIA release in the same support table, implying the automation/API layer is versioned release-by-release, though no explicit automation-API changelog text was retrievable — [Theorem Solutions release notes, cited via search]
- Installation practice note: a base GA release, service pack, and hotfix are installed sequentially on top of one another for a given CATIA V5-6 release — relevant context for "which SP/hotfix level" questions when debugging version-specific automation bugs — [Theorem Solutions installation docs, cited via search]
- A VBScript/VBA attach bug specific to version mixing: a forum user hit a problem getting a "CATIA V5R19" object from a VB script when a different (newer, R20) version was also installed, i.e. the ROT-based `GetObject` approach is sensitive to which versions are simultaneously registered/running — [eng-tips thread "get-catia-v5r19-object-from-a-vb-script-and-not-r20.362080"](https://www.eng-tips.com/threads/get-catia-v5r19-object-from-a-vb-script-and-not-r20.362080)

### Inferences
- For a "moderately recent" V5 release (anything from roughly R2017/R27 through the latest V5-6 R2020-class releases), the core Automation object model (Application/Documents/Selection/Viewpoint) appears to have remained stable enough that late-bound VB.NET/Python code written against one version has been reported to work across many versions (R18–R26 in one report) — but individual method-level regressions/crashes (e.g., a drafting-related method crashing specifically on R29) are plausible and should be tested against the exact target release and service pack rather than assumed.
- Favor internal command IDs over localized display-name strings when using `StartCommand`, since the one documented case of string breakage was a display-name issue, not an ID issue.

### Gaps
- No definitive, Dassault-sourced table mapping specific Automation API classes/methods to specific R-numbers (e.g., "X method introduced in R21," "Y method deprecated in R2019") was found. This would require direct access to Dassault's CAA Encyclopedia "What's New" pages per release, which were not reachable in this research session (network sandbox blocked non-allowlisted domains, and the full documentation is described elsewhere as license-gated).
- No confirmation of behavior on the very latest V5-6 2023/2024-era service packs; most forum evidence clusters around R18–R29-era discussions (roughly 2007–2018 forum post dates based on thread content), so currentness for a 2023+ install is uncertain.

## What are CATIA V5 macros (VBA/.CATScript/.CatVbs), and can they be triggered externally (COM call, command-line switch, keyboard shortcut) and bound to a toolbar button or key accelerator?

### Takeaway
CATIA V5 macros are VBA projects (typically run via Tools > Macro > Macros, or Alt+F8) or standalone `.CATScript`/`.CatVbs` script files; they can be triggered externally via (a) a COM call from an outside automation client (e.g., `Application.RunMacro`, or Python/`.NET` calling into the CATIA COM object and invoking the macro), (b) a command-line batch invocation of `CNEXT.exe -batch -macro <path>` (or via `CATSTART.exe`), and (c) assignment to a custom toolbar button or a keyboard accelerator inside CATIA's Tools > Customize dialog, which an external program could then trigger by injecting that exact keystroke. One important caveat repeatedly confirmed in forums: CATIA macros run **in-process**, so the CATIA UI freezes while a macro executes.

### Cited Findings
- Macros can be run from Tools > Macro > Macros, from a macros toolbar, or via the keyboard shortcut Alt+F8 — [search summary of SlideShare "Getting Started with CATIA V5 Macros" and related forum threads](https://www.slideshare.net/slideshow/getting-started-with-catia-v5-macros/43432616)
- Toolbar-button binding: a GitHub project for a CATVBA macro menu documents adding a macro as a toolbar entry via Tools > Customize, recommending doing this with no document open so the toolbar button is available in every workbench — [GitHub: kantoku-code/CATIA_V5_SimpleMacroMenu](https://github.com/kantoku-code/CATIA_V5_SimpleMacroMenu)
- Forum confirmation that custom keyboard shortcuts can be made for macros ("You can make keyboard shortcut also for macros"), though one user reports custom shortcuts "disappear when CATIA closes" and has to be reassigned on every launch — [eng-tips threads, cited via search] [3dswym idea: "Generate your own shortcuts in CATIA V5"](https://3dswym.3dexperience.3ds.com/idea/catia-user-community/generate-your-own-shortcuts-in-catia-v5_Yxl8hXyeSjmllp2qI40D9w)
- Toolbar-button code pattern: forum guidance is to place the macro invocation "in the button's click event" — the standard VBA UserForm/toolbar-button pattern — [eng-tips, cited via search]
- Explicit confirmation that **CATIA macros run in-process and block the UI**: "CATIA macros are run in-process, meaning CATIA essentially freezes while the macro is running" — [eng-tips thread, cited via search]
- **Command-line / batch triggering:** the documented pattern is `CNEXT.exe -batch -macro <full path to CATScript macro>` (quoted path), with an alternative via `CATSTART.exe` (slightly different command-line syntax) — [search summary of multiple forum/training sources, incl. Google Groups "Catia V5 Scripting"](https://groups.google.com/g/unogvense/c/ipFeev5d3V0)
- For unattended/headless batch runs, an IBM support note says the `CATSysForceBatchMode` environment variable is needed to let `CNEXT -batch -macro` run without a display; without it, a scheduled run "stayed frozen until someone logged on" — [IBM support note HD24315, cited via search]
- Related IBM bug report: a batch `CNEXT` process kept running even after `CATIA.Quit()` was called from within the macro, until `CATSysForceBatchMode=1` was set, which fixed correct process termination — [IBM support note HD98156, cited via search]
- **COM-triggered macro execution:** a forum answer confirms that calling `CATIA.StartCommand "Search..."` (i.e., driving CATIA's "power input" command bar from VBA) accomplishes what a user was trying to do with `SendKeys` — illustrating that COM-level command/macro invocation is considered the more reliable alternative to UI automation for this purpose — [eng-tips thread "how-to-the-sendkeys-with-vb-in-catia.253483"](https://eng-tips.com/threads/how-to-the-sendkeys-with-vb-in-catia.253483)
- PTC/Windchill integration documentation describes a supported pattern of invoking a specific named CATIA V5 macro (`WWGMTK_CATIAV5_MACRO`) from an external PDM client purely through environment variables and automation calls, as part of its "WWGM Toolkit" — confirming external, non-interactive macro invocation is an established integration pattern in industry, not just a forum hack — [PTC Windchill Help Center: "Create the CATIA V5 Macro to Invoke PDM Actions"](https://support.ptc.com/help/wnc/r12.1.0.0/en/Windchill_Help_Center/WWGMToolkit/wwgmtoolkit_create_CATIAV5_MACRO_PDM_Actions.html)
- No CATIA V5-specific "macro security level"/trust-center setting (of the kind VBA-hosting Office apps or BricsCAD have) was found in the sources searched; the only hits were unrelated products' settings (BricsCAD, Autodesk) or IBM bug reports about VBA macro *library* locking (a shared-drive `.catvba` library can lock out concurrent CATIA sessions from using it, fixed in R11 GA/V5R10SP04) — this is a confirmed **gap**, not a confirmed absence, since Dassault's own documentation wasn't reachable — [IBM support notes, cited via search]

### Inferences
- The most robust "trigger a macro from outside" architecture for a controller-input program is almost certainly: keep CATIA running interactively (not batch mode, which is for headless/unattended processing), and drive macros either (a) directly via COM (`Application` object's macro-run method, or the `StartCommand`/`Evaluate` patterns documented for pycatia) for discrete button-press actions, or (b) by pre-binding each desired macro to a specific keyboard accelerator inside CATIA, then having the external controller program inject that exact keystroke — this second approach is explicitly validated by 3Dconnexion's own recommended workaround (see prior-art section below) for exactly this kind of external-device-to-macro binding.
- Because macros block the CATIA UI while running, any macro bound to a controller input should be kept extremely short/fast (e.g., set a viewpoint, run one `StartCommand`) rather than doing heavy computation, to avoid perceptible input lag or the appearance of CATIA "hanging" on each button press.

### Gaps
- Dassault's own documentation on macro security/trust settings (if any exist in V5, unlike in VBA-hosting Office products) was not found or confirmed either way.
- No confirmed exact VBA method name/signature for "run this named macro from an external COM client" (e.g., whether it's literally `Application.RunMacro("ModuleName.MacroName")` or a different call) was independently verified against primary documentation — only the general existence of COM-triggerable macro execution was confirmed via secondary sources.

## Is injecting synthetic keyboard/mouse input (SendInput/PostMessage/SendMessage) targeted at the CATIA window a viable fallback, and what are the pitfalls?

### Takeaway
It is a documented, used-in-practice fallback (multiple eng-tips threads describe people doing exactly this against CATIA), but it is fragile and secondary to the COM API: `SendInput` generally requires the CATIA window to be the actual foreground/focused window (and multiple forum reports show mixed-to-poor results with `SendKeys`/`PostMessage` against CATIA specifically), while `PostMessage`/`SendMessage` can target a background window handle but are reported as "unreliable for simulating keyboard input" in general and specifically failed for at least one user trying to simulate a mouse click in CATIA via `FindWindowEx`+`PostMessage`. There's no evidence CATIA does anything like anti-cheat input filtering — the problems found are generic Windows message-pump/focus issues, not CATIA-specific blocking.

### Cited Findings
- General Windows behavior (not CATIA-specific, from gamedev/SO/HotkeyNet sources): "SendInput generally needs the target window in the foreground" to work reliably; one developer's testing found SendInput works for almost all games but requires the target to be the foreground window — [search summary of gamedev.net, Stack Overflow mirror, HotkeyNet docs]
- `PostMessage` reaches background windows but is considered unreliable for keyboard simulation; Raymond Chen (Microsoft) is cited as long arguing that simulating keyboard input via posted keyboard messages "is not reliable for many reasons"; one app accepted `PostMessage` keyboard input only when it also had actual keyboard focus — [Microsoft "Old New Thing" blog, cited via search](https://devblogs.microsoft.com/oldnewthing/20250319-00/?p=110979); [Stack Overflow mirror, "sendinput to background window"](https://kiwix.lema.org/stackoverflow.com_en_all_2023-11/questions/35408495/sendinput-to-background-window)
- For DirectInput-based applications specifically, a cited Stack Overflow answer states scancodes are needed and that `SendInput()` "is the only option" for that style of input handling — relevant context since CAD apps are not DirectInput-based, but shows the general technique landscape — [Stack Overflow mirror via search]
- **CATIA-specific attempts, from eng-tips forums:**
  - A user reported that `SendKeys` "nothing happens when using SendKeys to open windows" against CATIA — [eng-tips thread "how-to-the-sendkeys-with-vb-in-catia.253483"](https://eng-tips.com/threads/how-to-the-sendkeys-with-vb-in-catia.253483)
  - Another user got `SendKeys` to work for driving a dialog only by first forcing window focus (`WshShell.AppActivate "CATIA V5"`) and adding delays plus Tab-key sequences — explicitly a fragile, timing-dependent technique — [eng-tips, cited via search]
  - A user tried `FindWindowEx` + `PostMessage` to simulate a mouse click inside CATIA's 3D view and "couldn't get it to work" — [eng-tips, cited via search]
  - A separate forum report notes that even for a native CATIA command like Undo, the CATIA window still needed actual focus for the command to behave correctly ("Unavailable command: Undo" appeared otherwise) — reinforcing that CATIA's UI, like most native Win32/MFC-style apps, expects real foreground focus for keyboard-routed commands — [eng-tips, cited via search]
  - A user successfully used `mouse_event` with `MOUSEEVENTF_LEFTDOWN`/`MOUSEEVENTF_LEFTUP` (i.e., the legacy low-level mouse-event API, functionally similar to `SendInput` for mouse) to emulate a single click in CATIA as part of a view-placement macro workaround, but noted this didn't let them fully automate placing a view on a sheet — [eng-tips thread, cited via search]
  - A forum reply directly comparing approaches concludes: use CATIA's own COM/VBA API (`StartCommand`, or a CATScript) rather than SendKeys/window-message approaches, calling the API route "more reliable" — [eng-tips, cited via search]
- No evidence of any anti-cheat-style input filtering in CATIA was found in any source; the failures documented are consistent with ordinary Win32 focus/message-pump behavior, not deliberate blocking.

### Inferences
- For discrete, one-shot actions reachable via `StartCommand` or a macro, COM automation is clearly the preferred and more reliable route per direct forum consensus — input injection should be treated as a last resort specifically for interactive/continuous operations the Automation API can't reach non-interactively (e.g., smooth real-time orbit/pan driven by analog stick/gyro input, or driving a multi-step interactive command dialog).
- Given that `SendInput` needs real foreground focus and CATIA's own UI appears to behave like a normal focus-sensitive Win32/MFC app (not a DirectInput game), the practical implication for a controller-input program is: `SendInput` should work as long as the program ensures the CATIA main window is actually focused before sending keys/mouse events (e.g., via `SetForegroundWindow` plus appropriate focus-stealing workarounds, since Windows restricts `SetForegroundWindow` calls from background processes) — `PostMessage` to a background CATIA window handle is explicitly reported as unreliable for at least mouse-click simulation and should not be relied upon as the primary technique.
- A hybrid design is well-supported by the evidence: use COM `StartCommand`/macros for discrete button-mapped actions (workbench switches, predefined views, running tools) and use focused `SendInput` keystrokes only for continuous/analog camera movement (if a suitable keyboard-shortcut-driven continuous-pan/zoom/rotate mode exists in CATIA that can be modulated by repeated key events), or fall back to repeatedly setting `Viewpoint3D`/`Camera3D` via COM in a tight loop for smooth analog camera control instead of input injection at all.

### Gaps
- No direct, confirmed test report of `SendInput` specifically (as opposed to the older `SendKeys`/`PostMessage`/`mouse_event` APIs) being used against CATIA's 3D viewport for continuous camera manipulation (pan/zoom/orbit) was found — the closest evidence is general Windows guidance plus CATIA-specific `SendKeys`/`PostMessage` failure reports, not a confirmed `SendInput` success/failure case in CATIA.
- No information found on whether CATIA's 3D viewport responds to raw mouse-move + button-down WM_* messages the way it does to real HID mouse movement (relevant for emulating click-drag orbit/pan, which is the normal CATIA mouse-navigation idiom) — this would need direct testing against the target CATIA release.

## Is there prior art of joystick/gamepad/VR controller or custom-device (SpaceMouse-like) integration with CATIA V5, and what approach did they use?

### Takeaway
No GitHub repo, blog post, or forum thread combining a game controller/gamepad/joystick with CATIA V5 was found. The closest and best-documented prior art is 3Dconnexion's official SpaceMouse integration with CATIA V5-6 (built-in navigation modes plus a button-mapping layer), and — critically — a 3Dconnexion-forum-documented workaround where, after a SpaceMouse driver update broke CATIA's native button-customization panel, the recommended fix was to **assign a keyboard shortcut to a CATIA VB script/macro** and bind the SpaceMouse's programmable button to emit that same keystroke — i.e., exactly the "bind macro to a keyboard accelerator, then have the external device inject that keystroke" pattern.

### Cited Findings
- 3Dconnexion officially supports CATIA V5-6 and 3DEXPERIENCE CATIA with built-in navigation modes (Object Mode, Fly Mode, 2D Mode, Rotation Lock), view controls, and the ability to map arbitrary CATIA application commands onto SpaceMouse buttons, plus radial menus and macro support; some features are version-limited or must be toggled from inside CATIA rather than from 3Dconnexion's own settings — [3dconnexion.com CATIA features page](https://3dconnexion.com/applications/dassault-systemes-catia-v5/)
- Historical confirmation that SpaceMouse support for CATIA V5 goes back at least to "CATIA V5R19 SP4," per a Digital Engineering 24/7 article — [Digital Engineering 24/7: "3Dconnexion 3D mice now supported by Dassault Systèmes CATIA V5R19 SP4"](https://www.digitalengineering247.com/article/3dconnexion-3d-mice-now-supported-by-dassault-systemes-catia-v5r19-sp4/)
- **Button mapping / macro workaround (key prior-art finding):** on the 3Dconnexion user forum, a poster reports that "starting from v10 driver version, it is not possible anymore to really customize the spacemouse with CATIA" via CATIA's native Button Customization panel; a 3Dconnexion staff/community reply suggests the workaround: "Try assigning a keyboard shortcut to the catvbs script or module in CATIA" — i.e., bind the desired CATIA macro to a CATIA keyboard shortcut, then have the SpaceMouse driver's own button-mapping layer send that keystroke — [3dconnexion forum thread, "How to assign a Catia vb routine in SpaceMouse Enterprise"](https://forum.3dconnexion.com/viewtopic.php?p=65957)
- A separate poster in the same/related thread recommends the opposite-direction approach for ordinary (non-macro) commands: configure buttons through the 3Dconnexion driver's own properties window rather than CATIA's "Button Customization" panel, because the driver's button-mapping window already lists "the long list of Catia commands" directly — [3dconnexion forum, cited via search]
- Device-identification issue noted in the same forum ecosystem: some users reported CATIA detecting their 3Dconnexion device as the wrong model, which blocked button configuration entirely until resolved — a reminder that device/driver-identification bugs are a real practical obstacle independent of the automation technique chosen — [3dconnexion forum, cited via search]
- A Microsoft Community post describes someone attempting to use a gamepad (Xbox One controller) to drive an Excel VBA project (not CATIA specifically) — directly relevant as the nearest analog found for "gamepad → VBA-automatable Windows app," but the post received no replies/solution — [Microsoft Tech Community: "Excel Vba Project"](https://techcommunity.microsoft.com/t5/excel/excel-vba-project/td-p/1198312)
- No GitHub repository, blog post, or dedicated tutorial specifically combining a joystick/gamepad/VR controller with CATIA V5 automation was found despite multiple targeted searches (`"CATIA" joystick OR gamepad OR "game controller" github VBA automation`, `CATIA SpaceMouse joystick gamepad custom automation integration`) — this is a genuine, searched-for-and-confirmed absence of prior art for that specific combination, as distinct from the well-documented SpaceMouse case.

### Inferences
- The SpaceMouse-forum workaround is the single most directly transferable piece of prior art for the stated project: it validates, from an independent, non-CATIA-automation-focused community, the exact architecture of "bind a CATIA macro to a CATIA keyboard shortcut, then have an external input device's driver/program emit that keystroke to trigger the macro" — this is a proven pattern specifically because CATIA's own macro-to-shortcut binding was the thing being leveraged, not because of any deep SpaceMouse-specific CATIA integration.
- Since no gamepad/joystick-specific prior art exists, a DualShock4-to-CATIA controller program would be a genuinely novel integration; the project should expect to validate each technique (COM `StartCommand`/macro calls for discrete actions, keystroke injection for anything mapped to a shortcut, and possibly a tight-loop COM `Viewpoint3D` update loop for continuous camera motion) itself rather than copying a working reference implementation, since none was found.
- The Excel-VBA-plus-gamepad dead-end thread suggests that whatever gamepad-reading library/approach is chosen for the Windows side (e.g., XInput via a .NET or Python binding) is a solved problem independent of CATIA; the CATIA-specific risk is entirely on the "how do I get input from Windows into CATIA" side covered in the sections above, not on reading the DualShock4 itself.

### Gaps
- No confirmed working joystick/gamepad-to-CATIA project, blog post, or video was found anywhere in this research pass — if one exists, it is not well-indexed under the search terms tried (further searches specifically for "DualShock" + CATIA, or VR controller + CATIA, might be worth a follow-up pass but were not run here due to the call budget for this research scope).
- No information found on whether CATIA V5 has any native raw-HID/XInput reading capability of its own (unlikely, but not explicitly ruled out by any source found) that might bypass the Windows-input-injection question entirely.
